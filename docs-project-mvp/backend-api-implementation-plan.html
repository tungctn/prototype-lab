Plan triển khai Backend API cho prototype demo

Mục tiêu là có API thật đủ để FE mở workspace, tạo session, gửi prompt, xem tiến trình live bằng SSE, và preview hai route current / new. Bản này cố ý đơn giản, không GitHub branch, không queue phức tạp, không auth.

NestJS TypeORM PostgreSQL Local Folder Prototype SSE Live Events

1. Scope được duyệt để code

Backend sẽ quản lý metadata trong DB, còn source prototype vẫn nằm trong local app tại src/app/(prototype)/prototype/{session_slug}.

Khi tạo session: tạo folder session. Khi prompt đầu tiên: gọi sandbox fork để tạo current. Khi prompt cải thiện: copy current sang new, chỉ sửa new.

2. API list

GET /api/workspace

FE gọi khi mở màn hình demo để biết backend đang trỏ tới repo/local prototype root nào.

Input Không cần body.
DB Nếu chưa có workspace thì seed 1 record hard-code từ env hoặc config local.
Response 
{
  "id": "uuid",
  "name": "SNDQ Demo Workspace",
  "repoName": "sndq-fe",
  "prototypeRoot": "/Users/mac/Workspace/sndq/sndq/sndq-fe/src/app/(prototype)/prototype",
  "status": "ready"
}
Triển khai WorkspaceService.getOrCreateDemoWorkspace() dùng TypeORM repository, config path hard-code/env, không cần UI chọn repo ở bản demo.

POST /api/sessions

Tạo một phiên làm việc mới. Backend tạo session DB và folder {session_slug}, nhưng chưa tạo current/new cho tới khi user gửi prompt.

Request 
{
  "title": "Meeting feature A"
}
Filesystem Tạo folder: prototype/{session_slug}. Ví dụ: prototype/meeting-feature-a.
DB Insert chat_sessions với status=session_created, route_path=/prototype/{session_slug}, prototype_dir=.../{session_slug}.
Response 
{
  "id": "uuid",
  "title": "Meeting feature A",
  "routeSlug": "meeting-feature-a",
  "routePath": "/prototype/meeting-feature-a",
  "status": "session_created",
  "items": []
}
Triển khai SessionsController.create() validate title, generate slug đơn giản, tạo folder bằng Node fs.mkdir, lưu DB.

GET /api/sessions/:sessionId

Lấy lại trạng thái session để FE render header, chat và preview.

Input sessionId trên URL.
DB Query chat_sessions, join prototype_items, lấy messages gần nhất nếu cần.
Response 
{
  "id": "uuid",
  "title": "Meeting feature A",
  "status": "new_ready",
  "routePath": "/prototype/meeting-feature-a",
  "items": [
    {
      "kind": "current",
      "url": "/prototype/meeting-feature-a/current"
    },
    {
      "kind": "new",
      "url": "/prototype/meeting-feature-a/new"
    }
  ]
}
Triển khai Một service method getSessionDetail(), không cần phân trang ở bản demo.

GET /api/sessions/:sessionId/messages

Lấy lịch sử chat của session.

Input sessionId. Có thể thêm ?limit=50.
DB Query chat_messages theo session_id, sort created_at asc.
Response 
{
  "items": [
    {
      "id": "uuid",
      "role": "user",
      "content": "Tôi muốn cải thiện UI này",
      "createdAt": "2026-06-27T07:00:00.000Z"
    }
  ]
}
Triển khai Controller đọc DB trực tiếp qua service, chưa cần websocket/SSE cho history.

POST /api/sessions/:sessionId/prompts

API chính. FE gửi prompt, backend lưu message, chạy task local, và trả response nhanh. Tiến trình live đi qua SSE endpoint bên dưới.

Request 
{
  "content": "Tôi cần cải thiện UI phần meeting"
}
Nhánh xử lý Nếu session chưa có current: gọi sandbox fork để tạo current. Nếu đã có current: copy current sang new, rồi sửa new theo prompt.
DB Insert chat_messages(role=user). Sau khi task xong, insert/update prototype_items(kind=current|new) và update chat_sessions.status.
Response 
{
  "accepted": true,
  "sessionId": "uuid",
  "status": "processing"
}
Triển khai PromptsService.submitPrompt() lưu user message rồi chạy async fire-and-forget trong cùng process để demo nhanh. Không dùng queue. Nếu cần mock AI, service sẽ tạo/sửa file mẫu trong new.

SSE GET /api/sessions/:sessionId/events

FE mở EventSource để nhận log và trạng thái live trong lúc backend tạo/copy/sửa prototype.

Input sessionId trên URL.
Event mẫu 
event: session_status
data: {"status":"processing","message":"Đang xử lý prompt"}

event: current_ready
data: {"url":"/prototype/meeting-feature-a/current"}

event: new_ready
data: {"url":"/prototype/meeting-feature-a/new"}
DB Không cần lưu mọi event. Chỉ lưu message/status/item cuối cùng. Log live để trong memory.
Triển khai SessionEventsService dùng RxJS Subject theo sessionId. Controller dùng Nest @Sse(). Đủ cho demo local một process.

3. Thứ tự triển khai code

  1. Tạo DTO cho CreateSessionDto và SubmitPromptDto.
  2. Tạo PrototypeController gồm workspace, sessions, prompts, messages, events.
  3. Tạo WorkspaceService, SessionsService, PromptsService, SessionEventsService.
  4. Tạo PrototypeFilesystemService để mkdir, copy current sang new, build URL.
  5. Tạo SandboxForkService bản demo: gọi được skill/script sau này, trước mắt có thể mock tạo folder/file để FE thấy preview.
  6. Wire TypeORM repositories vào module, validate input bằng class-validator.
  7. Test bằng curl: workspace, create session, open SSE, submit prompt, get session detail.

4. Mapping với DB hiện tại

Table Dùng cho
workspaces Một workspace demo, giữ repo_name và prototype_root.
chat_sessions Một phiên làm việc, chứa slug/path/folder/status của session.
chat_messages Lưu prompt user và assistant note ngắn. Không lưu full streaming token.
prototype_items Lưu hai bản preview: current và new.

5. Demo behavior cụ thể

Prompt đầu tiên

POST /api/sessions/:id/prompts
"Tôi muốn cải thiện feature meeting"

Backend tạo current bằng sandbox fork, lưu item current, SSE bắn current_ready.

Prompt cải thiện tiếp theo

POST /api/sessions/:id/prompts
"Làm UI meeting gọn hơn"

Backend copy current sang new, sửa new, lưu item new, SSE bắn new_ready.

6. Những thứ cố ý chưa làm

  • Chưa auth, chưa multi-user, chưa permission.
  • Chưa GitHub branch/PR vì demo local folder là đủ.
  • Chưa queue worker; task chạy async trong Nest process.
  • Chưa lưu toàn bộ stream AI token vào DB; chỉ lưu kết quả/status.
  • Chưa quyết định Keep/Revise/Discard/Handoff/Promote vì flow hiện tại chỉ cần preview.
