Demo đơn giản nhất: API và Database cho prototype workspace

Mục tiêu của bản này không phải production architecture. Đây chỉ là thiết kế đủ để demo flow chat nhiều lượt: tạo session folder local, dùng sandbox-fork tạo bản current, rồi sửa bản new sau prompt cải thiện.

Simple First Hard-code OK Demo Only

1. Nguyên tắc làm đơn giản

Chỉ giữ những gì cần cho demo. Không cần queue thật, không cần event bus, không cần nhiều service, không cần workflow decision.

  • Frontend có thể gọi thẳng một backend nhỏ dạng Node/Express hoặc mock server.
  • Chat nên đi qua HTTP streaming hoặc SSE, chưa cần WebSocket.
  • Mỗi session có thể chứa nhiều prompt và nhiều câu trả lời của AI.
  • Khi tạo session, backend chỉ tạo folder parent theo session_slug.
  • Backend có thể hard-code việc đổi trạng thái từ saved sang ready.
  • Prompt đầu tiên gọi sandbox-fork để tạo current; prompt cải thiện copy current sang new rồi sửa new.
  • Workspace có thể chỉ có 1 record mặc định, không cần hệ multi-tenant đầy đủ.

2. Flow backend rất ngắn

1. Tạo session FE tạo session mới, backend tạo folder parent trong src/app/(prototype)/prototype/{session_slug}.
2. Gửi prompt Prompt đầu tiên gọi sandbox-fork, backend tạo route current với mock data.
3. Stream về UI Prompt cải thiện copy current sang new, rồi backend stream từng đoạn trả lời qua SSE.
4. Tạo updated preview Backend chỉ sửa route new và stream new_reloading / new_ready để FE mở bản mới.

3. API tối thiểu nên có

Method Path Dùng để làm gì Ghi chú demo
GET /api/workspace Lấy thông tin workspace hiện tại. Có thể hard-code chỉ trả về 1 workspace.
GET /api/sessions Lấy danh sách chat session. Dùng để render sidebar hoặc list conversation.
POST /api/sessions Tạo chat session và folder parent. Chưa tạo current/new ở bước này.
GET /api/sessions/:id/messages Lấy lịch sử chat của một session. Dùng khi reload trang hoặc mở lại session cũ.
POST /api/chat Nhận prompt mới và stream trả lời của AI. Response là SSE hoặc HTTP stream.
GET /api/sessions/:id/item Lấy prototype item hiện tại của session. Cho biết trạng thái saved, building, ready.

5. Database đơn giản nhất

Với chat nhiều lượt, nên dùng 4 bảng tối thiểu. Nếu muốn cực gọn thì vẫn có thể hard-code 1 workspace, nhưng nên giữ sessions, messages và items tách nhau. Session lưu folder parent; item lưu route current hoặc new.

Bảng Mục đích Field nên có
workspaces Lưu repo/project đang được demo. id, name, repo_name, repo_url, created_at
chat_sessions Lưu một cuộc trao đổi và folder parent của session. id, workspace_id, title, status, route_slug, route_path, prototype_dir, created_at, updated_at
chat_messages Lưu nhiều message trong cùng một session. id, session_id, role, content, created_at
prototype_items Lưu route current hoặc new được tạo từ prompt. id, session_id, kind, title, status, route_slug, route_path, url, created_at, updated_at

6. SQL phác thảo

create table workspaces (
  id varchar(40) primary key,
  name varchar(255) not null,
  repo_name varchar(255) not null,
  repo_url text,
  created_at timestamp not null default current_timestamp
);

create table chat_sessions (
  id varchar(40) primary key,
  workspace_id varchar(40) not null references workspaces(id),
  title varchar(255) not null,
  status varchar(40) not null default 'active',
  route_slug varchar(255) not null,
  route_path varchar(255) not null,
  prototype_dir text not null,
  created_at timestamp not null default current_timestamp,
  updated_at timestamp not null default current_timestamp
);

create table chat_messages (
  id varchar(40) primary key,
  session_id varchar(40) not null references chat_sessions(id),
  role varchar(20) not null,
  content text not null,
  created_at timestamp not null default current_timestamp
);

create table prototype_items (
  id varchar(40) primary key,
  session_id varchar(40) not null references chat_sessions(id),
  kind varchar(20) not null,
  title varchar(255) not null,
  status varchar(40) not null default 'saved',
  route_slug varchar(255) not null,
  route_path varchar(255) not null,
  url text,
  created_at timestamp not null default current_timestamp,
  updated_at timestamp not null default current_timestamp
);

8. Logic backend giả lập là đủ

  • Khi gọi POST /api/sessions, backend tạo record session và folder parent src/app/(prototype)/prototype/{session_slug}.
  • Prompt đầu tiên gọi sandbox-fork để tạo {session_slug}/current với mock data.
  • Khi gọi POST /api/chat, backend lưu user message vào chat_messages.
  • Ngay sau đó backend stream text trả lời dần qua SSE để FE render live.
  • Prompt cải thiện tiếp theo copy current sang new, rồi chỉ sửa code trong route new.
  • Endpoint chat có thể stream event current_ready, item_saved, new_reloading, new_ready.
  • Khi new sang ready, FE hiển thị hoặc reload panel new bằng item.url, đồng thời vẫn giữ current để so sánh.
  • Frontend không cần websocket, chỉ cần nghe stream của /api/chat và khi cần thì gọi GET /api/sessions/:id/item.

9. Những gì chưa cần trong bản này

  • Không cần auth phức tạp.
  • Không cần background job thật.
  • Không cần GitHub branch, push code, PR hoặc merge.
  • Không cần tạo current hoặc new ngay khi session vừa được tạo.
  • Không cần bảng preview environments riêng nếu URL có thể suy ra từ route.
  • Không cần websocket nếu chỉ stream chat và vài status event.
  • Không cần bảng decisions như keep, revise, discard, handoff, promote.
  • Không cần audit log hay versioning đầy đủ.
  • Không cần tách microservice, queue hoặc worker riêng.

10. Kết luận

Nếu mục tiêu là demo nhanh, cách hợp lý nhất là: 1 workspace, 1 bảng session có thông tin folder parent, 1 bảng message, 1 bảng item cho current/new, và một endpoint chat stream qua SSE. Như vậy đã đủ kể câu chuyện product tạo session, prompt đầu tạo current bằng sandbox-fork, prompt sau tạo new để so sánh.
