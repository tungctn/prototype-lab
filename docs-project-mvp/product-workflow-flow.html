Flow đơn giản: product nhìn thấy UI mới trên app thật

Bản này chỉ mô tả mục tiêu MVP đầu tiên: product user vào workspace, yêu cầu một UI/feature mới, và xem được UI đó chạy trong product thật thông qua sandbox. Chưa bàn decision workflow hay handoff.

Real GitHub Repo Sandbox New UI Preview

1. Ý chính

Product không cần nhìn code, không cần biết GitHub branch, không cần quyết định merge ở bước này. Product chỉ cần thấy bản hiện tại và bản UI mới trong app thật để so sánh ý tưởng có đúng hướng hay không.

2. Flow chạy

1

Product vào workspace

Frontend mở ra trang prototype. Repo/app demo đã chạy local, ví dụ social-media-web. Backend biết sẵn prototype root trong app.

2

Workspace dùng prototype route local

Prototype nằm trong route group (prototype), ví dụ src/app/(prototype)/prototype. Demo không cần tạo GitHub branch, push code hoặc PR.

3

Product bắt đầu session

Product tạo một session mới. Backend tạo folder parent theo slug, ví dụ meeting-feature-4.

Folder lúc này chỉ là khung session, chưa cần có current hoặc new.

4

Prompt đầu tiên tạo current

Product nhập prompt kiểu: Tôi muốn cải thiện màn building detail này. Backend lưu message và gọi sandbox-fork để tạo route current với mock data từ production page.

5

Prompt cải thiện tạo new

Product nhập prompt tiếp theo, ví dụ: Thêm UI meeting trong lease detail page. Backend copy current sang new, rồi chỉ sửa code/mock data trong new.

6

Product so sánh current và new

FE mở /prototype/meeting-feature-4/current và /prototype/meeting-feature-4/new. Đây là mục tiêu chính của flow: thấy bản hiện tại và bản UI mới trong app thật, không phải mockup rời.

3. Product cần thấy gì trên màn hình?

  • Tên repo/project thật đang dùng.
  • Folder session, ví dụ meeting-feature-4.
  • Ô prompt để fork current và prompt để tạo bản new.
  • Trạng thái current_ready, new_reloading, new_ready.
  • Panel current và panel new để so sánh.
  • App thật với UI mới nằm trong đúng layout hiện có.

4. Điều chưa cần ở MVP flow này

  • Chưa cần Keep, Revise, Discard, Handoff hoặc Promote.
  • Chưa cần GitHub branch, push code, PR hoặc merge về main.
  • Chưa cần workflow automation phức tạp.
  • Chưa cần backend thật cho toàn bộ feature mới.
  • Chưa cần product hiểu technical detail của sandbox-fork.

5. Cách hiểu hiện tại

Flow MVP là: product vào FE, app local đã setup, product tạo session, prompt đầu tiên dùng sandbox-fork để tạo current, prompt cải thiện tiếp theo copy current sang new rồi sửa new, sau đó product so sánh current và new trong app thật.
