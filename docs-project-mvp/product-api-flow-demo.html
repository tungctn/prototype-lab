Flow chốt: product chat, local session folder, current/new preview

Bản này mô phỏng flow thật ở FE và BE: màn hình gọi API nào, API trả gì, FE hiển thị gì, và preview panel cập nhật như thế nào sau khi product gửi prompt.

Product Flow SSE Chat Local Folder Current vs New

1. Kết luận ngắn

Khi product bắt đầu một session, backend chỉ tạo folder parent trong src/app/(prototype)/prototype/{session_slug}. Prompt đầu tiên dùng sandbox-fork để tạo route current. Prompt cải thiện tiếp theo copy current sang new, rồi chỉ sửa route new.

2. Flow thật từ FE đến BE

1

FE mở workspace

FE lấy project/repo đang demo để render header và trạng thái workspace.

GET /api/workspace

Hiển thị: repo name, prototype root path, trạng thái ready.

2

FE tạo session khi user bắt đầu feature mới

Backend tạo chat_session và folder session local. Chưa cần tạo current hoặc new ở bước này. 

POST /api/sessions
{
  "title": "Meeting UI for lease detail"
}

Hiển thị: card session, đường dẫn folder và trạng thái chờ fork màn hình.

3

Prompt đầu tiên tạo current bằng sandbox-fork

User nói muốn cải thiện màn nào. Backend/agent dùng sandbox-fork để clone màn production sang route current với mock data. 

POST /api/chat
{
  "session_id": "sess_001",
  "message": "Tôi muốn cải thiện màn building detail này..."
}

Hiển thị: current panel mở sau khi nhận current_ready.

4

Product gửi prompt cải thiện UI

FE gọi chat API lần tiếp theo và đọc response stream qua SSE/HTTP streaming.

POST /api/chat
{
  "session_id": "sess_001",
  "message": "Thêm UI meeting trong lease detail page"
}

Hiển thị: user message trong chat, AI response chạy live từng đoạn.

5

BE lưu chat và update route new

Backend copy current sang new, lưu user message, tạo hoặc update prototype_items, rồi chỉ sửa code trong route new. 

cp -R meeting-feature-4/current meeting-feature-4/new
edit src/app/(prototype)/prototype/meeting-feature-4/new/page.tsx

Hiển thị: trạng thái saved, updating new version.

6

FE reload new khi stream báo ready

Khi nhận new_reloading, FE hiển thị loading trên panel new. Khi nhận new_ready, FE reload iframe new hoặc để dev server hot reload. 

event: new_ready
data: {
  "session_id": "sess_001",
  "new_url": "http://localhost:3000/prototype/meeting-feature-4/new"
}

Hiển thị: current giữ nguyên, new có UI mới.

4. API contract chốt

Thời điểm API FE dùng response để hiển thị
Mở workspace GET /api/workspace Repo name, prototype root path, workspace ready.
Bắt đầu feature mới POST /api/sessions Session id, route slug, prototype folder.
Reload session cũ GET /api/sessions/:id/messages Lịch sử chat.
Gửi prompt POST /api/chat Lần đầu tạo current, lần sau tạo/update new.
Cần lấy item hiện tại GET /api/sessions/:id/item Prototype item status, title, route path.

6. Trạng thái FE cần xử lý

Status/Event Ý nghĩa FE làm gì
status = session_created Folder parent của session đã có. Hiển thị session và chờ prompt fork màn hình.
current_ready Sandbox-fork đã tạo route current. Set iframe current bằng current_url.
item_saved Prompt đã tạo prototype item. Hiển thị card/item đang xử lý.
new_reloading Backend đang sửa route new. Overlay loading lên panel new.
new_ready Bản new đã sẵn sàng sau prompt. Reload iframe new hoặc clear loading nếu dev server hot reload.

7. Những gì chưa cần cho bản chốt này

  • Chưa cần Keep, Revise, Discard, Handoff, Promote.
  • Chưa cần GitHub branch, push code, PR hoặc merge.
  • Chưa cần bảng branches riêng vì demo chạy bằng folder local.
  • Chưa cần bảng preview environment riêng vì URL suy ra từ route local.
  • Chưa cần WebSocket vì stream một chiều từ BE về FE qua SSE là đủ.
  • Chưa cần deploy preview thật vì Next.js dev server local đọc route mới.
  • Chưa cần tạo current hoặc new ngay khi session vừa được tạo.

8. Câu chốt

Flow demo nên được hiểu là: FE mở workspace, tạo session, BE tạo folder parent dưới (prototype)/prototype. Prompt đầu tiên chạy sandbox-fork để tạo current. Prompt cải thiện tiếp theo copy current sang new, sửa code trong new, rồi FE reload panel new khi nhận new_ready.
